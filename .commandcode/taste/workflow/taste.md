- Guard shared/prewarmed fallback data against WAF/network failures — but never assume the failure is transient. Confidence: 0.75

- When a React Query hook uses a dynamic queryKey (e.g., debounced search term) alongside a full-page skeleton on `isLoading`, the fix must include `placeholderData: (previousData) => previousData` in the useQuery call — debouncing alone is insufficient. Without it, each query key change creates an empty-cache query, `data` goes undefined and `isLoading` flips true, firing the skeleton and remounting the entire page (losing input focus). The placeholderData preserves the previous result set on screen during refetch, keeping isLoading false. Confidence: 1

- For remote/encrypted media (e.g., WhatsApp link-preview thumbnails), matching the payload field names is not enough for other clients to decrypt the media — the CDN media class implied by the upload path/type matters. A thumbnail uploaded via the sticker/link-thumbnail pipeline (`/o1/v/t24/f2/m234/...`, `t24` class) renders fine on the sender's own Web client but shows a pitch-black banner on receivers even with `mediaKey`/`mediaKeyTimestamp`/`thumbnailEncSha256` all present, because receivers derive the decryption key using the media class embedded in the CDN path. However, the media-class swap alone is NOT a sufficient fix: after switching to the regular image media pipeline (`WAWebMediaMmsV4Upload.uploadMedia`, producing `/v/t62...enc`, the same class WA's native crawl uses), the user still reported "and still the pitch black banner" — so keep diagnosing the remaining decryption mismatch (key derivation / plaintext-vs-encrypted hash pairing) rather than assuming a correct-class upload closes the case. Diagnose by diffing the fallback directPath against the known-good native thumbnailDirectPath in the same log dump. The decisive diff turned out to be the FULL field set, not the CDN class: the known-good native payload carries ONLY `thumbnailDirectPath` + `thumbnailSha256` (plus inline `thumbnail`/`thumbnailHQ`) — verified ABSENT of `mediaKey`, `mediaKeyTimestamp`, and `thumbnailEncSha256`. Remote clients derive the decryption key from server-embedded material in the CDN directPath (`oh=` param) and verify plaintext against `thumbnailSha256`, so injecting extra key/hash fields that mismatch the server-side state actively poisons decryption (pitch-black banner). When replicating a working system's output, prefer EXACT field parity with the known-good reference (fewer fields, not "more complete" payloads), and use the server-stored plaintext hash (`mediaObject.filehash`) for the verification field rather than a locally recomputed one. Confidence: 0.6
